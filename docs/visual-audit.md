# 启程视觉与工程审计

## 现有架构

- Maven 管理 Java 21 和 Spring Boot 3.4.5。Spring MVC 同源托管 `src/main/resources/static/index.html` 与 `/api`。浏览器加载原生 ES Modules、CSS 和 Canvas。
- 数据通过 Spring Data JPA 访问。项目支持 PostgreSQL 和用于本地预览的 H2。LLM、LangGraph 面试与匹配服务、招聘数据源是否可用由后端配置决定。前端以实际返回为准。
- `atelier/main.js` 读取 Hash，区分地点封面和 `work=1` 工作页。旧的 `?view=…` 入口仍由路由映射处理。切换页面会终止所属视图的读请求和 Canvas 循环。
- `atelier/api.js` 处理同源请求、响应封装、JSON、multipart 与文件下载。`ui.js` 提供模板转义、原生对话框、状态反馈与任务按钮。简历草稿存在模块内，正式版本、会话与诊断由服务端持久化。
- 首屏艺术资源是本地 WebP，西文字体是本地 WOFF2。浏览器端图片 OCR 在需要时加载 Tesseract。项目观察室依赖服务端 JavaParser 解析 Java 源文件，ZIP 限制为 5 MB。

## 保留的页面与契约

| 入口 | 重要操作 | 真实接口 |
| --- | --- | --- |
| `#studio?work=1` | 创建、编辑、导入、导出、版本保存与对比、事实锁定、教育核验 | `/api/resumes`、`/api/resumes/import`、各简历的 `pdf`、`versions`、`fact-locks`、`education-verification` |
| 简历工作台的辅助操作 | ATS 检查和报告、写作指导、项目草稿、学习路线 | `/api/ats/check`、`/api/ats/report`、`/api/resume-guidance`、`/api/learning-paths` |
| `#jobs` 与 `#jobs?work=1&sector=java&role=java` | 方向聚焦、城市与关键词筛选、查看详情、按简历匹配、查看依据、带着岗位去练习 | `/api/jobs`、`cities`、`city`、`recommend`、`recommend/agent`、`refresh`、岗位详情和 `similar` |
| `#interview?work=1&job=…` | 选择简历与岗位、选择难度、逐轮作答、恢复会话 | `/api/interviews`、`/api/interviews/{id}`、`/api/interviews/{id}/answers` |
| `#growth?work=1` | 查看历史、练习反馈、生成岗位相关简历诊断 | `/api/dashboard`、`/api/interviews`、`/api/diagnoses`。诊断由后端验证同一简历与岗位的面试证据 |
| `#project?work=1` | GitHub 或 ZIP、证据题单、逐题追问 | `/api/project-questions`、`/upload`、`/follow-up` |

岗位内容分两种来源。职业方向和角色说明由前端提供，具体招聘记录来自 API。预览的示例招聘记录有明确标记。岗位与诊断分数来自后端，在新版中置于可展开的依据区。

## 旧版视觉诊断

| 页面 | 原因 | 对应改动 |
| --- | --- | --- |
| 城市地图 | 首屏标题、地标和导航都在同一张夜景上竞争。暗遮罩消耗了画面本来可以表达的距离与建筑细节，地图和底部导航缺少相互反馈。 | 主视觉以单独的版面承载地标。导览文字落在有边界的纸张上，任务入口、地标和交通路线联动。 |
| 简历 | 图像与长表单各自成立，封面的纸张语言进到工作区后中断。 | 封面做展开的跨页，内页改成可以边编边校对的案头。纸张的底色、版边、保存反馈贯穿两层。 |
| 面试 | 两张座位缩略图像设置选项。点击后还要寻找独立的开始入口。 | 座位直接成为入口。桌面聚焦预览空间，移动端一次点按即可进入指定难度。 |
| 天文馆 | 方向面板固定在右下方，可能盖住右侧星球。画面有空间，岗位层级却要靠说明理解。 | 面板移到馆名下，收拢职责和岗位链接。星球环、职业资料和实际岗位用连贯的层级展开。 |
| 花园 | 封面有自然光，进入后又回到常见打分面板，设计语义从回顾变成评估。 | 改为温室与记录页，优先显示逐轮反馈和下一步行动，分项评分收进依据。 |
| 项目 | 旧表单同时展示两类来源，且图纸只作为封面装饰。 | 来源切换对应正确输入。工作台的扫描只在真实请求期间运行，结果阅读先问题，再展开源码行号和代码。 |

## 状态与风险

- 原生 Hash 路由和数据契约适合当前体量。GSAP、Motion 可简化大型时序编排，Three.js、React Three Fiber 可实现连续 3D 探索，Rive 适合复杂角色状态机。这版只有短转场、局部 Canvas 动画与表单状态，继续使用浏览器原生方案，避免额外运行时与资产加载。
- Canvas 按 DPR 上限 2 绘制，隐藏页和关闭动效时暂停。地点元素采用 DOM 链接或按钮，以便独立聚焦、命中和直接打开。
- 城市地标与图片位置是手工对齐的美术数据。替换地图必须重做地标和移动构图。
- 岗位筛选保存在当前 Hash，浏览器返回和直接打开该地址会恢复筛选。简历草稿、未发送的当轮回答及项目题单留在当前网页的会话内。保存后的简历、历史面试与诊断继续由服务端管理。
- OCR 依赖外部资源，图片加载失败时仍可粘贴已识别文字。岗位 Agent、模型润色、外部招聘和公开 GitHub 读取依赖配置或网络。
- 诊断生成按简历与岗位定位最近的面试证据。逐轮反馈按用户选择的具体会话展示，避免把两类数据混为一谈。

### 实测结果

- Edge 的 1440 × 900 与 1366 × 768 视口检查了六个封面。首页另做了地标命中检查。对比静态截图后修正标题换行、岗位目录首屏密度与旧星体图中的无关文字，替换了全部场景的主图。
- 运行时核对了快捷入口、键盘焦点、Escape、前进和返回、四颗星球的选择、星球与目录的共享转场、动效开关和系统减少动态效果。桌面检查未发现脚本异常或请求失败。
- 在独立 H2 演示实例验证简历创建与编辑、两个 PDF 下载、ATS、版本对比与恢复、写作指导的 AI 润色选项、岗位匹配与筛选恢复、五轮面试与草稿恢复、复盘诊断。GitHub 使用随仓库打包的固定源码样例，另实测 ZIP 上传，两条路径均得到带源码证据的追问。
- `mvn.cmd -q -B package` 构建成功，24 项 Maven 测试通过。JavaScript 语法检查和 Git 差异检查通过。桌面截图见工作目录旁的 `motion-shots/wayforward-covers.jpg` 和 `motion-shots/wayforward-workspaces.jpg`。
- 本地预览使用示例岗位和本地推理。在线模型、外部实时招聘与远程 GitHub 可用性由部署环境决定，本轮实测使用演示实例与固定样例。
