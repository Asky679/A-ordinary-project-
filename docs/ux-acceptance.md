## 桌面验收路线

1. 在首页直接点咖啡馆建筑外墙或门牌。进入后点击画面里的窗边圆桌或里间入口，确认工作页的难度和座位一致。选简历与岗位后开始，查看设置是否自动收起。提交一轮后，在首页通过「继续模拟面试」回到刚才的会话。
2. 在天文馆点击 Java 星球，再点一次确认仍停在星图。打开「Java 开发工程师」，确认首屏能看到真实接口返回的岗位。使用浏览器返回，星球应保持选中。
3. 在简历编辑台跳到「项目经历」，填写一项并观察右侧纸面标记。完成面试后，从成长记录切换面试和诊断，打开建议依据。项目分析完成后，展开题目，再按需打开源码证据。

## 验证记录

- Edge 实测 1440 × 900 和 1366 × 768。检查六个场景、建筑命中、导航联动、键盘操作、页面直达、前进返回、动效关闭和接口不可用时的首页入口。
- 独立 H2 实例完成简历保存与 PDF 导出、ATS 检查报告导出、版本对比和恢复、岗位筛选与匹配、面试五轮与草稿恢复、成长记录和诊断。公开 GitHub 仓库和本地 ZIP 均成功生成题单，并返回带源码证据的追问。GitHub 请求有一次超过 30 秒，重试成功。
- Maven 打包通过，24 项测试通过。JavaScript 语法和 Git 空白检查通过。
- 本轮沿用现有场景插画和后端接口。在线模型和生产招聘源未列入本轮验收。


## 与 GitHub main 的桌面版对接

基线为远端 95343ec。新版入口使用启程页面，旧书签的 view 参数仍可进入相应工作台。预览地址为 http://127.0.0.1:4181/，使用独立的本地 H2 数据库。部署环境沿用仓库的 PostgreSQL、Qdrant 和 LangGraph 配置。

| 页面 | 对接与验收重点 |
| --- | --- |
| 简历仓库 | 检索已保存的简历，打开指定简历、切换预览版式、导出服务器 PDF |
| 岗位目录 | 普通搜索、简历匹配、混合检索、全局和单岗权重、Agent 推荐的成功或不可用状态 |
| 面试咖啡馆 | 选岗位加载蓝图，八轮文字问答、刷新恢复和完成后的诊断。证据卡不显示，现有后端兼容逻辑继续使用 |
| 求职准备 | 真实工具记录、岗位链接、已有面试入口、技能节点关系和个性化学习路线 |
| 项目观察室 | 仓库地址或 ZIP、真实源码证据、调用高亮与后续追问 |

动效遵循全站开关。岗位蓝图、工具轨迹和源码结果按真实请求状态展示。
